/proc is the file system which is used by ps to get the process related details...

By listing the proper directory like structure, we can easily get the details what we wanted..

Through proc interface, we can communicate with kernel...

With /proc/<pid>/status, we can easily read and parse the content regarding the process..

In stat, there are 5 states. They are 
1. R -> Running
2. S -> Sleeping
3. D -> Uninterruptible sleep
4. Z -> Zombie
5. T -> Terminated or Stopped

Now, The main difference between D and S are, D is the sleep which can't be interrupted by the signals or interrupts like SIGKILL, but S can be killed or interrupted. 

Eg: scanf would be in S, just waiting for the input, nothing else, so, we can easily kill it by Ctrl + C, nothing much. For a disk reading operation, if the kernel is waiting for the disk reading to occur, the process will enter into the D state, as, killing or interrupting at middle won't be making the process enter into the safe state..

The Zombie process is a process, where, the process exits, but the entry is still in the process table, as the parent still didn't call wait(), as wait() is the system call with which, the parent process knows the info that, whether the child process is successful or not. After the parent process calls wait(), the kernel provides the info about that and deletes the entry of the process in the Process table. 

How can we delete the zombie process?
1. We can make the parent process call wait(), with which, the entry disappears.
2. The parent process can be deleted, so that, the zombie process is mapped to the init process as child, then the init calls the wait() method to delete the entries of the child process.

The main learning here is, ps is the tool that parses the content in the proc filesystem.

In comm file in the /proc, the name of the process is there.
In the cmdline file, the command is there..

There are two types of error codes or signals in filestream. They are 
1. Failbit
2. Badbit


Failbit - Operation is failed, but the stream is usable. 
Eg: For cin>>x, if someone enters characters, then extracting integer fails, so, failbit set. 
Opening a nonexistent file, trying to read a line after reaching the end of the file, all these contribute to failbit. 

Badbit - I/O error or corruption of the stream. Very rare, Hardware I/O failures, OS-level read errors, Loss of connection to a network backed stream.

There is an another bit called eofbit, which is set at the end of the file. 

Generally, ifstream does not set any exception, so, for exceptions, we need to set them manually with filestream.exceptions();

Underlying difference between failbit and badbit is, the task can't be done, but the stream is fine - failbit, the stream itself is getting corrupted because of underlying errors - badbit.
